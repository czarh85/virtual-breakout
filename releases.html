01End of run

What happens after a run ends was rebuilt around one idea: show the result first, and let the next run start clean.

  • changeChanged the game-over screen so that your score arrives first, in large digits, with the gap to the next record right under it.
  • newThe wreck of your ship drifts from the depth where it exploded, and the screen names the sector you reached.
  • newA high score table: five places, arcade style, with its own screen in the menu and factory scores from 2500 down to 500.
  • newName entry for a run that makes the table: a double-height alphabet, no timer, and only START signs — nothing is confirmed by accident.
  • fixFixed an issue where a second run could start with the previous run's score.
  • fixFixed an issue where the key press that closed one screen also closed the next one.
  • changeChanged game over, score table and pause so that they share one margin, with a clear row under the big digits.

02Ball, ship and collision

The physics were rewritten so that the rule you see is the rule the game applies.

  • changeChanged ball physics so that its position is tracked to the pixel, and every collision reads that same pixel.
  • fixFixed an issue where the ship returned balls it was not touching.4 px of gap, about ten times per run → 0
  • fixFixed an issue where a ball striking the seam between two bricks broke only one of them.
  • changeChanged the back shelf so that it uses one scale for everything: the far ball is 12 px.
  • newThe side save: the hull is solid over its whole height, so a ball caught from the side comes back — flat, and far.
  • newThe aiming mark shows where the ball will hit, and it reads the same rule as the ball.
  • changeChanged transitions so that the ship freezes during guardian intros, tallies and its own explosion.
  • changeChanged the serve so that a fixed prompt comes first, then blinks; A serves only once it is shown.
  • changeChanged WIDE HULL so that it is 72 px at the front and its collision box matches the drawing.
  • newLaser cannons drawn on both hulls, normal and wide, front and back.

08Under the hood

What keeps the fixes above from coming back.

  • changeMeasured the brick cap before building the editor on it: 24 or 28 visible bricks stop the console, 21 do not.
  • changeThe release test battery was itself repaired: two of its stations had been red, or silent, on healthy builds since V1.04.
  • changeThe publishing script now archives the previous current ROM from the live registry and refuses to publish if any version would disappear.without it, V1.04 would have been overwritten
  • changeThe manual's asset check now proves identity by regenerating the file, not by comparing dates.5 assets wrongly called stale
  • changeThe manual and this site were rebuilt from this exact ROM: every capture carries the fingerprint of the build it came from.

09Where this was wrong

In this release, 8 conclusions had to be taken back — most of them by the tools meant to catch mistakes:

  • The release battery reported the boot screen red for a week. The build was fine: the check was judging the engine's own splash page as if it were the game.
  • The long sessions meant to watch the ball cross the pipes never left that splash page on a release build. Their 22 frames of circuit board were read as near; once the demo did run, the ship's hull was read as the word far.
  • A laser shot was declared unable to break a pipe on a test where the laser never fired.
  • The planet stripes were first blamed on the moon backdrops. They were clean; the stripes were in another asset.
  • A capsule rotation the player had approved was replaced by a wobble, without saying so.
  • The plan to fix the mix would have lowered the title theme — undoing a bass the player had asked to hear.
  • Five assets were declared stale on their dates. Regenerated, they were identical to the byte.
  • The first publication of this very release was one step from overwriting V1.04.

A check that has never been seen failing is not a check.

10Known issues

Open, and each one named rather than hidden:

  • Crossing the pipes cannot be watched automatically: the demo hides the plane banner. It is checked on the console.
  • Catching a back-shelf capsule at the back, two bonuses in a row, a bomb blast on the bonus brick and the Scavenger's capsule were not observed in the emulator: the ball is lost before a scripted test can reach them. They are on the console checklist.
  • Winning a test stage and winning a whole series in the editor were not observed in the emulator for the same reason.
  • The Colossus' back-shelf shield was not seen rising in a 20-second recorded fight. It is checked on the console.
  • Each guardian having its own pattern and animation is designed, and scheduled after this release.

The rule this project runs on is unchanged: an item closes when it is fixed, when it is proven not to exist, or when it is explicitly refused.

09Where this was wrong

A changelog that lists only victories is a marketing document. Over these days, 11 conclusions recorded in this project had to be taken back:

A diagnosis reversed itself once the sprites were examined magnified. A memory leak was announced — there was no leak, and the earlier conclusion was the error. A plan rested on a premise that was false, and the specification already said so. Two corrections had to be applied to a commit made the same day. A hypothesis was refuted by arithmetic before it cost a build.

And a change to the sound was flashed to the cartridge without replaying the sound measurement. The instrument existed — in a throwaway script, in a temporary folder, dead by the next morning.

An instrument that lives in a draft is not an instrument.

2 independent external audits were run against the code in this period. The second was commissioned specifically to find the class of defect the first could not see. Both found real defects, and both sets are in the lists above.

10Known issues

Open, tracked, and each carrying its own evidence:

  • The ball's exact collision box is deliberately held back until a verdict comes back from the console, rather than changed ahead of one.
  • The non-regression lock does not yet cover guardian fights. Two distinct causes, both identified.
  • Twelve batches from a campaign that was stopped mid-flight were converted into tracked follow-ups rather than quietly dropped.

The rule this project runs on: an item closes when it is fixed, when it is proven not to exist, or when it is explicitly refused. « We will live with it » is not one of the three.
